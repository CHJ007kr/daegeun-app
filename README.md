# 대근 관리 웹앱

정유1팀 교대근무자의 휴가 등록, 대근 요청, 대근 신청, 근무 달력을 관리하기 위한 내부용 웹앱입니다.

현재는 HTML, CSS, JavaScript로 동작하며 사용자 정보와 일정 데이터는 브라우저 `localStorage`에 저장합니다. 추후 Firebase를 연결하여 여러 사용자가 동일한 휴가·대근 데이터를 공유하고 푸시 알림 기능을 추가할 예정입니다.

## 이 문서의 역할

이 README는 앞으로 기능을 수정하기 전에 반드시 확인해야 하는 개발 기준 문서입니다.

1. 작업을 시작하기 전에 README와 실제 코드를 함께 확인합니다.
2. 요청 사항이 이 명세와 충돌하면 임의로 코드를 변경하지 않고 충돌 내용을 먼저 알립니다.
3. 정책 변경이 명확하게 승인된 경우에만 구현과 README를 함께 갱신합니다.
4. 한 화면의 변경이 다른 화면의 일정 표시나 저장 데이터에 미치는 영향도 함께 검증합니다.
5. 기존 `localStorage` 및 `calendarEvents` 데이터는 명시적인 승인 없이 삭제, 초기화 또는 비호환 형태로 변환하지 않습니다.

- 사용자별 휴가·대근·교육 일정 필터
- 하루 휴가 및 달력 범위 선택 방식의 연속 휴가 등록
- 과거 날짜와 휴무일의 신규 휴가 등록 차단
- 연속 휴가에서 실제 주간·야간 근무일만 날짜별 개별 이벤트로 저장
- 연차 최초 인접조 모집과 일부 신청 후 전체 타 조 확대 규칙
- 연차 외 휴가의 전체 타 조 모집 규칙
- 대근 대상의 동일 근무지역(`area`) 및 역할(`role`) 조건
- 대근 신청, 신청시간 변경, 필요시간 초과 차단 및 신청 취소
- 연차 대근일의 휴가자 교대조 기준 근무 표시
- 모집중·모집완료 요청 분리와 완료 목록의 접이식 표시
- 지난 대근 요청은 요청 화면에서만 숨기고 원본 일정은 보존하는 동작
- 과거 대근의 시간 변경 및 취소 금지
- 휴가 취소 시 활성 claim 제거와 `cancelledClaims` 보관
- 휴가 등록 달력과 근무 달력을 열 때 현재 월로 초기화하는 동작
- 대한민국 공휴일 표시와 교대근무 계산의 독립성
- 테스트 사용자 전환과 전환 직후 설정·사용자 요약 갱신
- 기존 `calendarEvents`와 사용자 `localStorage` 데이터 보존

## 교대근무 패턴

기본 8일 패턴은 다음과 같습니다.

`주 → 주 → 휴 → 휴 → 야 → 야 → 휴 → 휴`

기준일은 `2026-12-02`이며 조별 offset은 다음과 같습니다.

- 1조: `0`
- 2조: `6`
- 3조: `4`
- 4조: `2`

사용자의 교대조 변경 이력은 `shiftChanges`에 저장합니다. 날짜별 실제 교대조는 `getShiftForDate()`로 구하고, 해당 교대조와 8일 패턴으로 실제 근무를 계산합니다.

특수 맞교대나 정기보수 기간의 근무 변경은 향후 `shiftOverrides` 또는 Firebase 데이터로 관리할 예정입니다. 현재 코드에는 별도의 `shiftOverrides` 기능이 없습니다.

## 사용자 정보

사용자별로 다음 정보를 관리합니다.

- 이름: `userName`
- 교대조: `userShift`
- 근무지역: `userArea`
  - NO.1 PROCESS
  - NO.2 PROCESS
  - WWT
- 근무 역할: `userRole`
  - 기술장
  - 보드
  - 현장

현재 사용자 정보는 `localStorage`에 저장합니다.

## 휴가 등록 규칙

### 하루 휴가

달력에서 날짜 하나를 선택하고 휴가 종류를 선택하여 등록합니다.

- 과거 날짜에는 신규 휴가를 등록할 수 없습니다.
- 실제 교대근무가 `휴`인 날짜에는 휴가를 등록할 수 없습니다.
- 같은 사용자가 같은 날짜에 같은 종류의 휴가를 중복 등록할 수 없습니다.
- 휴무 여부는 `getShiftForDate()`를 반영한 실제 근무 결과로 판단합니다.

### 연속 휴가

연속 모드에서 달력의 첫 번째 선택일을 시작일, 두 번째 선택일을 종료일로 사용합니다. 월을 이동하여 서로 다른 달의 날짜도 범위로 선택할 수 있습니다.

선택한 기간의 모든 날짜를 검사하여 다음과 같이 처리합니다.

- 주간 근무일: 날짜별 휴가 이벤트와 대근 요청 생성
- 야간 근무일: 날짜별 휴가 이벤트와 대근 요청 생성
- 휴무일: 자동 제외
- 과거 날짜가 포함된 범위: 등록 불가
- 동일 날짜와 동일 휴가 종류의 기존 이벤트: 중복 생성 방지

예를 들어 실제 근무일이 5일 포함되어 있으면 휴가 이벤트와 대근 요청도 날짜별로 5건 생성합니다. 연속 휴가는 별도의 묶음 데이터가 아니라 기존 단일 휴가 이벤트 구조를 사용하여 근무일별 개별 이벤트로 저장합니다.

## 사용자별 달력 표시

### 휴가 등록 달력

현재 사용자 기준으로 다음 일정만 표시합니다.

- 내가 등록한 활성 휴가
- 내가 다른 사용자의 요청에 신청한 대근

다른 사용자의 휴가 자체는 표시하지 않습니다.

### 근무 달력

현재 사용자 기준으로 다음 일정을 표시합니다.

- 내가 등록한 활성 휴가
- 내가 신청한 대근
- 내가 등록한 교육 및 기타 일정

과거 휴가·대근·교육 기록도 삭제하지 않고 계속 조회할 수 있습니다.

## 대근 요청 대상 규칙

대근 대상 판정은 다음 공통 함수를 사용합니다.

- `getTargetShiftGroups(request)`: 휴가 종류, 휴가자 조, 신청된 시간과 남은 시간을 기준으로 대상 조 계산
- `canUserReceiveDaegunRequest(request, user)`: 대상 조와 사용자 이름, 근무지역, 역할을 함께 확인
- `hasUserClaimedDaegun(request, userName)`: 기존 신청자인지 확인

대상 사용자는 휴가자와 이름이 달라야 하며 다음 조건을 모두 만족해야 합니다.

- 근무지역(`area`)이 같아야 합니다.
- 근무 역할(`role`)이 같아야 합니다.
- 요청 날짜에 적용되는 실제 교대조가 대상 조에 포함되어야 합니다.

이미 해당 요청에 신청한 사용자는 대상 조가 달라지더라도 기존 신청시간을 확인하고 변경할 수 있습니다.

### 연차 최초 요청

연차는 신청된 대근시간이 `0`일 때 인접 조에만 요청합니다.

- 1조 휴가 → 2조, 4조
- 2조 휴가 → 1조, 3조
- 3조 휴가 → 2조, 4조
- 4조 휴가 → 1조, 3조

### 연차 일부 대근 후

연차 12시간 중 일부 대근이 잡히고 `remainingHours > 0`이면 휴가자의 조를 제외한 모든 조로 모집 대상을 확대합니다.

예:

`2조 연차 12시간 → 1조 사용자가 8시간 신청 → 4시간 남음 → 1조, 3조, 4조 대상 모집`

### 연차 외 휴가

전반차, 후반차, 전반반차, 후반반차는 최초 요청부터 휴가자의 조를 제외한 모든 조가 대상입니다.

예:

`2조 전반차 → 1조, 3조, 4조 대상`

이 대상 계산 로직은 향후 Firebase 푸시 알림에서도 그대로 재사용하며, 현재는 실제 알림을 발송하지 않습니다.

## 대근 신청 규칙

연차는 여러 사용자가 필요한 시간을 나누어 신청할 수 있습니다.

예:

- 김철수 8시간
- 박영희 4시간
- 합계 12시간으로 모집 완료

대근자는 대근 요청 화면과 근무 달력의 날짜 상세에서 본인의 신청시간을 직접 변경할 수 있습니다.

예:

- 12시간 → 8시간
- 8시간 → 4시간
- 4시간 → 8시간

시간 변경은 기존 claim의 `hours`를 수정하고 `claimedHours`, `remainingHours`, `status`를 다시 계산하는 방식입니다. 다른 대근자의 신청시간을 합산했을 때 `requiredHours`를 초과하는 변경은 허용하지 않습니다.

대근 신청 취소도 가능하며, 취소 후 남은 시간에 따라 요청 상태를 다시 계산합니다.

## 대근 요청 상태와 목록

- `status === "모집중"`: 대근 요청 화면 상단에 표시
- `status === "완료"`: 기본적으로 접힌 `대근 모집 완료` 영역에 표시
- 오늘보다 이전 날짜의 요청: 대근 요청 화면에서만 숨김

지난 요청을 숨길 때 원본 `calendarEvents`를 삭제하지 않으므로 과거 대근자의 근무 기록은 유지됩니다.

## 연차 대근 근무표 표시

연차 대근의 경우 대근자의 원래 교대조가 아니라 휴가자의 교대조 근무표를 기준으로 해당 날짜의 주간·야간·휴무를 표시합니다. 휴가자의 교대조는 요청에 저장된 `request.shift`를 사용합니다.

예:

`2조 사용자가 연차 등록 → 3조 사용자가 대근 신청 → 대근자의 근무 달력은 해당 날짜를 2조 근무 기준으로 표시`

이 규칙은 연차에만 적용합니다. 전반차, 후반차, 전반반차, 후반반차 대근은 대근자 본인의 기존 근무 계산을 유지합니다.

## 휴가 취소 정책

오늘 또는 미래 날짜에 본인이 등록한 휴가는 취소할 수 있습니다. 과거 날짜의 휴가는 기록 보존을 위해 취소할 수 없습니다.

취소 전 확인 문구는 대근자 유무에 따라 달라집니다.

- 대근자가 없을 때: `이 휴가를 취소하시겠습니까?`
- 대근자가 있을 때: `현재 대근자가 등록되어 있습니다. 휴가를 취소하면 대근 일정도 함께 취소됩니다. 계속하시겠습니까?`

확인창에서 취소를 선택하면 데이터를 변경하지 않습니다. 휴가 취소를 확정하면 다음과 같이 처리합니다.

- 휴가 이벤트에 `cancelled: true`와 `cancelledAt` 기록
- 취소 직전 claim 복사본을 `cancelledClaims`에 보관
- 활성 `claims`를 빈 배열로 변경
- `claimedHours`를 `0`으로 변경
- 대근 요청 화면에서 해당 요청 제거
- 휴가 등록 달력과 근무 달력에서 연결된 대근 일정 제거

`cancelledClaims`는 향후 Firebase 취소 알림 수신자 계산에 사용할 기록입니다. 실제 푸시 알림은 아직 구현하지 않습니다.

향후 알림 예시는 다음과 같습니다.

> 9월 24일 최희주님의 휴가가 취소되어 대근 일정도 취소되었습니다.

## 과거 대근 기록

오늘보다 이전 날짜의 대근 기록은 조회만 가능합니다.

- 신청시간 변경 불가
- 대근 취소 불가
- 휴가 등록 달력과 근무 달력에서 기록 조회 가능
- 대근 요청 화면에서는 지난 요청 숨김

과거 날짜라는 이유로 `calendarEvents` 또는 claim 데이터를 삭제하지 않습니다.

## 달력 동작

휴가 등록 화면과 근무 달력을 열 때마다 현재 로컬 날짜의 연·월로 초기화합니다.

예를 들어 현재 날짜가 `2026-09-02`이면 두 화면 모두 처음에 2026년 9월을 표시합니다.

- 휴가 등록 화면 재진입: `calendarDate`, `selectedDate`, 연속 휴가 시작일·종료일 초기화
- 근무 달력 재진입: `workCalendarDate`, `workSelectedDateValue`와 선택 상세 초기화
- 화면 안에서는 이전·다음 달 이동 가능
- 오늘 이전 날짜는 회색 톤으로 표시하지만 기존 기록은 숨기지 않음

## 대한민국 공휴일

`holidays.js`에서 2026~2050년 대한민국 공휴일과 대체공휴일을 정적 데이터로 관리합니다.

달력의 날짜 숫자는 다음 색상 규칙을 사용합니다.

- 일요일: 빨간색
- 공휴일과 대체공휴일: 빨간색
- 토요일: 파란색
- 평일: 기본 색상
- 과거 날짜: 회색 톤과 낮은 강조

공휴일이 토요일이면 공휴일의 빨간색 표시를 우선합니다. 날짜를 선택하면 상세 영역에 공휴일 이름을 표시합니다.

공휴일은 시각적 정보일 뿐이며 `getWorkType()`을 포함한 교대근무 계산에는 영향을 주지 않습니다. 선거일이나 임시공휴일처럼 미래에 확정되는 날짜는 임의로 생성하지 않고, 확정 후 `holidays.js`의 추가 공휴일 데이터에 등록합니다.

## 현재 저장 방식

현재 테스트 단계에서는 `localStorage`를 사용합니다.

주요 저장 항목은 다음과 같습니다.

- `userName`
- `userShift`
- `userArea`
- `userRole`
- `shiftChanges`
- `calendarEvents`

`calendarEvents`에는 휴가, 대근 claim, 휴가 취소 상태, 교육 및 기타 일정이 함께 저장됩니다. 브라우저 데이터가 삭제되거나 기기를 변경하면 저장된 데이터가 사라질 수 있습니다.

## 향후 Firebase 적용 계획

Firebase 연결 후 다음 데이터를 서버에서 공유할 예정입니다.

- 사용자 프로필
- 휴가
- 대근 요청
- 대근 신청
- 교육 일정
- 알림

교대패턴 계산과 공휴일 데이터는 Firebase에서 읽지 않고 현재처럼 앱 내부에서 계산·관리하여 Firestore 읽기 사용량을 최소화합니다.

## 향후 알림 기능

예정된 알림은 다음과 같습니다.

1. 휴가 등록 시 대근 대상자에게 요청 알림
2. 대근 신청 시 휴가자에게 알림
3. 연차 일부 대근 후 남은 시간이 있으면 대상 확대 알림
4. 휴가 취소 시 `cancelledClaims`에 저장된 기존 대근자에게 취소 알림
5. 대근 전날 대근자에게 일정 알림

## 개발 상태

현재 개발·테스트 단계입니다. Firebase 연결 전까지 동일 기기의 `localStorage` 데이터를 사용하여 테스트 사용자를 전환하면서 기능을 확인합니다.

테스트 사용자는 다음과 같습니다.

- 최희주 / 2조 / NO.2 PROCESS / 현장
- 김철수 / 1조 / NO.2 PROCESS / 현장
- 박영희 / 3조 / NO.2 PROCESS / 현장

테스트 사용자로 전환하면 `userName`, `userShift`, `userArea`, `userRole`이 즉시 변경되고 사용자 요약과 설정 화면이 갱신됩니다. 현재 테스트 편의를 위해 전환 시 `shiftChanges`는 초기화됩니다.
